目前使用 Claude Code 存在一个较为普遍的问题：账号容易被封禁，即使付费订阅，也无法完全避免这一风险。

一种更稳定的方式是：通过 Google 的 Antigravity IDE 使用 Claude 模型。

![img](/images/2026/1774355625707_A4A397CE-3AE8-442f-8096-D9CD71D7C63C.png)

Antigravity IDE 内置了 Sonnet 4.6 Thinking 和 Opus 4.6 Thinking，并且目前提供一定的免费额度。

同时，Claude 与 Google Gemini 的额度是分开的，当 Claude 配额用完后，可以无缝切换到 Gemini 继续使用，提高整体可用性。

在模型选择上：

Sonnet 适合作为日常默认模型，具备较强的推理能力、稳定的编程表现，以及更快的响应速度和更高的性价比。

Opus 更适合复杂任务，例如大型代码库重构、高复杂度分析、长上下文处理，以及深度链式推理。

两者均属于当前较新的推理模型，覆盖从日常到高阶的大部分使用场景。

在稳定性方面，Antigravity 中的 Claude 服务是通过 Google 作为企业代理提供的 API 接入。

相比个人直接使用 Claude，依托 Google 账号体系（如 Gmail、Google Docs、Google Play 等），整体账号稳定性通常更高，风险相对更低。

原因在于，Google 账号本身承载了邮箱、文档、应用分发等多项核心服务。

一旦账号被封，影响的不只是单一产品，而是整个账号生态。

因此，这类封禁操作的决策成本更高，平台在处理时通常会更加审慎。
